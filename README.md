Official website for **[Further Engine](https://github.com/SametGkTe/Funky-Further-Engine)** — a free, open-source Psych Engine fork for Friday Night Funkin'.

Live at **https://further-engine.github.io**

## Project layout

```
.
├── index.html              # markup only (was a single 3,200-line file)
├── 404.html                # branded not-found page
├── status.json             # site-wide notice banner (see below)
├── robots.txt / sitemap.xml / site.webmanifest / favicon.ico
├── src/
│   └── input.css           # Tailwind source + custom CSS  ← edit this
├── assets/
│   ├── css/
│   │   ├── app.css         # GENERATED by Tailwind — do not edit by hand
│   │   └── icons.css       # self-hosted icon set (CSS masks, no CDN)
│   ├── js/
│   │   ├── app.js          # site logic: auth, profiles, leaderboard
│   │   ├── releases.js     # live GitHub release data (version, links, downloads)
│   │   ├── router.js       # hash router: real URLs, back button, per-page SEO
│   │   ├── motion.js       # scroll reveals + the home page's live top-5 strip
│   │   └── admin.js        # staff moderation panel (#/admin)
│   └── img/
│       ├── screens/        # in-game screenshots (WebP)
│       └── ...             # logo, favicons, OG card
├── docs/                   # SQL to run in the Supabase SQL editor — NOT served
│   ├── supabase-leaderboard-fix.sql
│   ├── supabase-multi-account.sql
│   ├── supabase-multi-account-debug.sql
│   └── supabase-admin-panel.sql
├── .github/workflows/css.yml   # fails CI if app.css was not rebuilt
└── tailwind.config.js
```

Load order matters: `app.js` defines `showPage()` and publishes `window.FurtherEngine`
(Supabase URL/key, `FLAGS`, `getAvatarUrl`); `motion.js`, `admin.js` and `router.js`
build on it. All four are `defer`, and each retries briefly if `app.js` has not
finished, so the order in `index.html` is a convenience rather than a hard
requirement.

The `docs/` folder is documentation for the maintainer. GitHub Pages will happily
serve `.sql` files, so never put credentials in them — everything there is schema
and queries only.

## Working on the site

Static HTML — just open `index.html`, or serve the folder:

```bash
python3 -m http.server 8080
```

### Changing styles

`assets/css/app.css` is **generated**. Edit `src/input.css`, then rebuild:

```bash
npm install          # once
npm run build        # one-off, minified
npm run dev          # watch mode while you work
```

Commit the regenerated `assets/css/app.css` — GitHub Pages serves it directly, no build step runs on deploy.

Tailwind scans `index.html`, `404.html` and `assets/js/**/*.js` for class names
(`tailwind.config.js`). If you add classes anywhere else, add that path to the
`content` array or the classes will be purged.

## Site notice banner

`status.json` drives the amber banner at the top of the page. Leave `message`
empty to hide it:

```json
{ "title": "", "message": "" }
```

Set a message to show it instantly (the file is fetched with `cache: no-store`):

```json
{ "title": "WARNING", "message": "Server maintenance — leaderboard disabled" }
```

## Release data is automatic

`assets/js/releases.js` reads the GitHub Releases API at page load and fills in:

* the version badge in the navbar and the "latest stable build" line,
* every download card's link, file size and platform,
* the real total download count in the hero stats,
* the release date and "release notes" link.

Cut a new release on GitHub and the website updates itself — nothing to edit
here. Results are cached in `sessionStorage` for 30 minutes; if GitHub is
unreachable the values shipped in the HTML stay put.

## Leaderboard

`assets/js/app.js` renders the board from two Supabase views:
`global_leaderboard` (Ultra Points) and `achievement_leaderboard`.

Features worth knowing about:

* **Country filter** — the dropdown and the "top countries" chips are built
  from whatever countries actually appear in the data, with player counts.
* **Filters are deep-linkable.** The state is mirrored into the URL, so
  `#/leaderboard?country=Turkey&sort=level&page=2` can be shared or bookmarked,
  and a bare `#/leaderboard` always means "unfiltered".
* **Global ranks.** Filtering or searching never renumbers players — a row
  always shows the player's real worldwide position.
* **Pagination** — 25 rows per page (`LB_PER_PAGE`), with the podium occupying
  ranks 1–3 when no filter is active.
* **Mobile layout** — country, level and accuracy collapse under the username
  instead of overflowing the table.
* **Auto refresh** every 42 s, but only while the leaderboard page is visible
  and the browser tab is in the foreground.
* **Escaping.** Usernames and badges are user-controlled and go through
  `escapeHtml()` before they touch `innerHTML`.

## Backend

Accounts, profiles, avatars/banners and the leaderboard live in Supabase
(project `ubhglndbbzidunjgnpqi`). The publishable key in `assets/js/app.js` is
public by design — **all** access control must be enforced by Row Level
Security policies and RPCs on the Supabase side, never by the client.

Server-side checks still worth having:

* username validation and profanity filtering (the `BADWORDS` list in `app.js`
  is a convenience for users, not a security control),
* score submission validation,
* storage upload size/type limits on the `avatars` and `banners` buckets.

### Applying the SQL

The files in `docs/` are not run automatically. Paste them into the Supabase SQL
editor in this order, once per project:

| File | What it does |
|---|---|
| `supabase-leaderboard-fix.sql` | Grants `anon` the `EXECUTE` it needs on `is_banned`, which the leaderboard views call. Without it the board returns 401. |
| `supabase-multi-account.sql` | IP logging (`record_ip`), the `/24`+`/64` grouping, registration limits, review views, ban/hide helpers. |
| `supabase-admin-panel.sql` | The RPCs behind `#/admin`. |
| `supabase-multi-account-debug.sql` | Diagnostics. Only needed when something looks wrong. |

Two Supabase traps these files document, because both cost real debugging time:

* `alter default privileges ... grant all on functions to anon` means
  `revoke ... from public` does **not** remove anon's access. You need an explicit
  `revoke execute on function X from anon;`.
* `auth.audit_log_entries.payload` is `json`, not `jsonb`, so the `?` operator
  fails until you cast. Supabase also prunes that table, so historical IPs may
  simply not exist — IP data starts accumulating from the moment `record_ip()`
  ships.

## Anti-alt-account system

Registration calls `can_register_from_here()` before creating an account
(2 per 24h, 3 total per IP group, **fail-open** — a backend hiccup must never
block a legitimate signup). Every sign-in fires `record_ip()`.

The browser never sends an IP; Postgres reads it from the Cloudflare header, so
it cannot be spoofed from the client. IPs are pruned after 90 days by
`prune_account_ips()`, and the FAQ discloses the retention period.

## Moderation panel (`#/admin`)

Visible only to profiles with `role` of `admin` or `founder`:

```sql
update public.profiles set role = 'founder' where username = 'YourName';
```

**The hidden nav link is not the security boundary.** Every RPC calls
`require_admin()` inside Postgres, so forcing the page open in devtools yields
403s and empty tables. Admins cannot moderate other admins. The page is marked
`noindex` and never overwrites the canonical URL.

Three views: risk-scored suspects, shared IP groups, and duplicate mailboxes
(Gmail dot/plus normalisation). Every action is manual and confirmed — a shared
household or school IP is not evidence of cheating.
